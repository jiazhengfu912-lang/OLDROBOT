# OLDROBOT

[English](README.md) | 简体中文

这是一个面向三轴总线舵机机构的 STM32F103C8 裸机固件。固件上电后先执行固定动作序列，随后通过 HC-05 蓝牙串口接收单字节控制命令。

## 当前行为

复位后，固件依次执行：

1. 初始化 HAL、72 MHz 系统时钟、GPIO、USART1 和 USART2。
2. 启动 USART2 单字节中断接收，并输出 `System start`。
3. 闪烁 PB5 状态 LED，等待电源和舵机稳定，然后让三个舵机回到初始姿态。
4. 执行已启用的三步上电固定动作，并再次回到初始姿态。
5. 轮询最新收到的蓝牙命令，并分派对应动作。

应用直接使用 STM32 HAL，采用阻塞式执行方式，没有使用 RTOS。

### 引脚与串口映射

| MCU 引脚 | 功能 | 应用用途 |
| --- | --- | --- |
| PA9 | USART1 TX，115200 8N1 | 连接总线舵机控制板 RX |
| PA10 | USART1 RX，115200 8N1 | 已配置，但当前应用不读取 |
| PA2 | USART2 TX，9600 8N1 | HC-05/调试文本输出 |
| PA3 | USART2 RX，9600 8N1 | HC-05 单字节命令输入 |
| PB5 | 推挽输出 | 状态 LED |
| PA13 / PA14 | SWDIO / SWCLK | SWD 下载与调试 |

舵机应使用满足其规格的电源，并确保 STM32、蓝牙模块、舵机接口板与舵机电源共地。源码没有记录完整的电气电平和舵机供电方案，接线前必须查阅实际硬件数据手册。

## 控制接口

USART2 每次接收一个 ASCII 字节作为命令，同时支持大写和小写形式。

| 命令 | 当前行为 | 舵机目标值 `(ID1, ID2, ID3)` | 运动时间 |
| --- | --- | --- | --- |
| `A` / `a` | 执行动作 A | `(200, 600, 500)` | 800 ms |
| `B` / `b` | 执行动作 B | `(800, 400, 300)` | 800 ms |
| `C` / `c` | 执行动作 C | `(500, 500, 500)` | 700 ms |
| `R` / `r` | 回到初始姿态 | `(610, 480, 490)` | 1000 ms |
| `S` / `s` | 发送广播停止命令 | 不适用 | 立即发送命令 |

收到有效动作命令时会翻转 PB5。状态和错误文本通过 USART2 返回。

舵机协议帧包含两个 `0x55` 帧头、ID、长度、命令、参数和取反累加校验和。位置参数限制在 `0..1000`，运动时间限制在 `0..30000` ms。

## 上电动作

`Core/Src/main.c` 中的 `POWER_ON_ACTION_ENABLE` 控制是否执行固定上电动作。

| 步骤 | 舵机目标值 `(ID1, ID2, ID3)` | 运动时间 | 下一步前延时 |
| --- | --- | --- | --- |
| 初始姿态 | `(610, 480, 490)` | 1000 ms | `Servo_InitPose()` 内等待 1100 ms，随后 `main()` 再等待 1200 ms |
| 1 | `(485, 555, 415)` | 800 ms | 1000 ms |
| 2 | `(795, 405, 565)` | 700 ms | 900 ms |
| 3 | `(485, 555, 415)` | 700 ms | 900 ms |
| 回初始姿态 | `(610, 480, 490)` | 1000 ms | `Servo_InitPose()` 内等待 1100 ms，随后再等待 1200 ms |

动作组先通过 `SERVO_MOVE_TIME_WAIT_WRITE` 写入待执行位置，再发送启动命令。当前 A/B/C 处理函数使用广播 ID `0xFE` 启动动作。

## 软件结构

| 路径 | 职责 |
| --- | --- |
| `Core/Src/main.c` | 初始化、上电动作、USART2 命令接收、当前动作组和主循环 |
| `Hardware/servo_bus.c` | 总线舵机组帧、参数限幅、发送、启停控制和初始姿态 |
| `Core/Src/usart.c` | USART1 和 USART2 HAL 配置 |
| `Core/Src/gpio.c` | PB5 状态 LED 配置 |
| `Drivers/` | 工程附带的 STM32F1 HAL 和 CMSIS 源码 |
| `MDK-ARM/` | Keil 工程、启动代码、设置和生成的构建产物 |

一条典型命令链路如下：

`USART2 中断 -> HAL_UART_RxCpltCallback() -> bt_cmd/bt_cmd_flag -> 主循环 -> Process_BT_Command() -> servo_bus -> USART1 协议帧`

## 构建

工程包含 Keil 项目，但没有命令行构建脚本。

1. 安装支持 Arm Compiler 6 的 Keil MDK 和 STM32F1 Device Pack。
2. 使用 µVision 打开 `MDK-ARM/OLDROBOT.uvprojx`。
3. 选择 `OLDROBOT` Target。
4. 通过 **Project > Build Target**（`F7`）构建。
5. 预期生成 `MDK-ARM/OLDROBOT/OLDROBOT.axf` 和 `MDK-ARM/OLDROBOT/OLDROBOT.hex`。

以上 GUI 步骤根据工程文件推导。本次文档编写期间，PATH 和默认本地安装路径中均未找到 µVision，因此没有提供未经验证的 CLI 构建命令。

## 已知限制

1. **CubeMX 时钟冲突：**`OLDROBOT.ioc` 记录了 AHB 2 分频和 36 MHz HCLK，但当前执行的 `SystemClock_Config()` 使用 AHB 1 分频，因此在 8 MHz HSE、PLL 9 倍频下实际 HCLK 为 72 MHz。使用 CubeMX 重新生成代码前必须先消除该冲突。
2. **只保存最新命令：**USART2 回调只保存一个当前命令和一个标志。阻塞动作期间收到的新命令可能覆盖尚未处理的旧命令。
3. **阻塞式动作链路：**上电动作、姿态切换和动作辅助函数都使用 `HAL_Delay()`，延时期间主循环不能调度其他工作。
4. **动作定义重复：**`Hardware/servo_bus.c` 导出了 `Action_Group1/2/3`，但当前蓝牙链路使用 `main.c` 中另外定义的 `Action_Group_A/B/C`。编号动作组没有接入当前应用流程。
5. **错误状态 LED 无法持续闪烁：**`Error_Handler()` 先关闭中断，再调用 `HAL_Delay()`。HAL Tick 不再更新后，程序可能停在第一次延时，无法持续翻转 PB5。
6. **舵机链路只有发送：**当前应用只发送 UART 协议帧，不解析舵机应答，也不确认实际位置。驱动注释还指出某些接口板可能需要半双工方向控制，但当前没有实现。
7. **没有自动化测试：**工程没有包含主机侧或目标板侧测试套件。
